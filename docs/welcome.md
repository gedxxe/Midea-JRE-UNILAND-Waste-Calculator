# Energy Record welcome

The fullscreen dark **Energy Record** welcome uses the supplied white Midea logo, a brief localized slogan, the requested heart credit and one sign-in action. The page has no inset frame. A circular mask opens one centered glass sign-in card; Back reverses the same mask toward the original sign-in action. The native Back button has a rounded outline and arrow. Its final layout is present from the first circle frame, so the form does not shift when the reveal ends. Both surfaces are inert during the transition. Resize, reduced motion, hidden tabs or motion-off settle at the intended destination, while session changes remain authoritative. The former duplicate title, slogan, large blue logo/replay controls and signed-out build footer are removed. Header language selection and public blank-reading templates remain available.

Existing sessions go straight to their protected destination; required password changes open their form directly. Logout clears the account workspace before showing the welcome. The app does not remotely inspect physical meters. The credit remains “Made with ❤️ by gedxxe for Midea JRE Engineering Department”; the established reporting attribution is unchanged.

## Source and boundaries

Tech Text, Split Text, Magnet, Gradient ASCII, Glass Icons, GlassSurface and Lattice Loader are adapted from the official [React Bits source](https://github.com/DavidHDev/react-bits/tree/e12c22192ac7b4b452c5e2feb9b586d74765d696), pinned to that commit. This is an application-specific DOM/canvas adaptation, without React, GSAP, external fonts or additional packages. The full **MIT + Commons Clause License Condition v1.0** is retained in [asset/licenses/react-bits.txt](../asset/licenses/react-bits.txt), with file provenance in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). The supplied logo retains separate brand rights.

- ui/welcome-tech.js follows the supplied actual TechText engine: metrics entrance, dashed outer glyph silhouettes, selection frames/dimension labels/specks, click-kick and draggable spring return. It caches filled/dashed sprites at DPR 1.5, blits at fractional positions and requests native animation frames only during active/settling motion. Intro duration follows elapsed time even with dropped frames; spring integration stays bounded. No autonomous outline sweep or nearest-character selection outside glyph bounds; leaving restores solid characters. The main title follows the selected language: Energy Record, 能源记录, Catatan Energi.
- ui/welcome-ascii.js contains the upstream WebGL2 Gradient ASCII engine with the supplied blue/white horizon palette, full canvas opacity and cursor scrambling (at most 24 trail points). It targets 30 fps when idle and up to 60 while a pointer trail is active, with a maximum 1200 x 720 framebuffer. A quarter-resolution field and early exit over unused trail slots limit fragment work; glow is disabled, retaining two render passes. Dark areas remain transparent as in the source. Local contrast gradients protect text without dimming the entire scene. It releases GPU resources on leaving and creates a fresh canvas on Back. The small cached title artwork remains suspended during signed-out login so the reverse reveal has a complete title; authentication destroys that decoration too. Unsupported/lost WebGL keeps a static dark CSS gradient.
- ui/welcome-magnet.js bounds the native CTA decoration to 10 pixels. signin-effects.css adapts the layered Glass Icons CSS fallback; its WebGL refraction renderer is not included.
- ui/signin-transition.js shows Lattice Loader while the actual sign-in request is pending, clears it on error and fades it after a successful identity update. It never delays the request or account/password gates. Its completion fade has a bounded cleanup fallback if interrupted.

ui/glass-surface.js adapts the supplied GlassSurface SVG displacement/color-channel composition and frosted fallback. It generates geometry-only owned Blob maps on size changes, revokes them on destruction and adds no render loop, external origins, backdrop screenshots or form-value access. Text remains outside the filtered layer. Optional module/filter failure retains the CSS surface and native controls. ui/dialog-motion.js owns lazy glass and the native blank-template dialog: 320 ms entrance, 220 ms close, Escape, focus return and interrupted-motion cleanup. Its X icon has a localized accessible label. The sign-in card uses the same surface after the circle reveal.

The blank-template dialog uses theme-matched translucent controls, inset native-select chevrons and thin native scrollbars with a transparent track. Desktop selectors share a row; mobile selectors stack. The readonly preview remains a native, selectable text area with both scroll directions and normal scroll chaining. Only the dialog body scrolls on short screens, keeping the glass frame, heading and copy/download actions in place. Its displayed/copy/download content is unchanged. Fields add no extra blur layers or rendering loop; keyboard focus and platform high-contrast controls remain available.

welcome.css owns the hero/circle reveal. glass.css owns these surfaces and the inset language chevrons. logo.css owns the centered sign-in card. ui/welcome.js loads optional effects independently and coordinates presentation with the existing account controller. Decoration has no credentials, account records, meter data, storage or API access. Nothing changes report calculations, persisted data or analytics.

## Motion and fallback

The title area starts visually blank, including before app initialization and in all three languages. Its semantic heading stays available to assistive technology while the canvas prepares. The title, background and CTA modules settle independently. A failed title effect shows plain text; a stalled import falls back after three seconds of active welcome time, and a late response does not replace it with a new intro. Pause, reduced motion and motion-off retain a complete static title. Without JavaScript, a noscript title remains visible. No loading delay gates sign-in.

Letter artwork is capped at DPR 1.5 and rasterized only when layout, language or fonts change. The supplied canvas selection and spring engine repaints while interacting or settling, then stops; no idle title loop remains. Background frame targets are upper bounds, not a hardware-independent frame-rate guarantee. Pause, hidden tabs, an open modal, offscreen scenes, reduced motion, leaving the welcome and data-motion="off" stop optional rendering. Touch scrolling is not intercepted; touch does not leave an outlined character. Reduced motion uses the HTML title, static gradient and direct form opening. Loading feedback remains readable without animation.

Each optional module can fail without preventing native sign-in. Canvas/context loss, repeated Back navigation, resizing, preference changes and interrupted circle/completion transitions must leave usable controls. Forms retain labels, autocomplete, focus order and service errors. Short screens use normal page scrolling. The full static asset budget stays below 925 kB, including the supplied 260 kB PNG. Effects add no database requests or writes; device performance still varies.

## Verification and rollback

Browser regressions cover rendered-pixel restoration, source metrics/selection/drag behavior and cached glyph rasterization on hover, pointer-driven background pixels, reversible/interrupted navigation, idle/frame bounds, pause/visibility/preferences, unsupported/lost WebGL, repeated Back, centered three-language forms, pending/failed/successful sign-in, password gates, deep links and logout. Existing calculation, draft, historian and monitoring suites remain required. Visual review uses synthetic accounts.

No database, session or saved-data migration is required. Use a normal revert PR to return to the previous presentation. Keep the upstream license with any distributed build and preserve existing release tags/branches. See [release and rollback](releases.md). Preview login remains unconfigured.
